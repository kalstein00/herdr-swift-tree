# 원격 Helper 도입 조건과 첫 버전의 성능 보장 범위

원격 Linux에서는 먼저 기존 Herdr와 대상 서버에 이미 있는 기능으로 유휴 목록 조회 0회와 RTT 20 ms에서 단일 변경 반영 p95 1초 이하를 같은 구성으로 검증한다. 기존 경로로 두 조건을 함께 충족할 수 없어 별도 Helper가 필요하다고 확인되면, 관리자 권한과 서버의 인터넷 접속 없이 배포하고 일반 사용자 권한으로 실행할 수 있는 Helper를 허용한다. 추가 구성 요소의 설치·업데이트 부담을 피할 수 있는 환경은 기존 경로를 우선한다. [검증 조건](../research/herdr-files.md#유휴-조회와-변경-감시-복구)

## #9 결정

첫 제품 후보에는 Herdr의 기존 원격 실행과 서버의 GNU `stat`을 사용한다. 펼친 폴더의 메타데이터가 달라지면 그 폴더의 자식 목록을 갱신한다. QEMU ext4의 같은 연결과 같은 열린 폴더를 유지한 상태에서 유휴 목록 조회 0회와 생성·삭제·이름 변경 각각 p95 1초 이내를 확인했다. 원격 Helper 배포와 Herdr upstream 변경 없이 이 경로로 첫 제품 후보를 검증한다. [측정 결과와 재현 조건](../verification/remote-watch-feasibility.md)

주기적 메타데이터 확인 비용은 열린 폴더 수와 연결 상태에 따라 달라진다. 재연결이나 감시 중단으로 변경을 놓쳤을 가능성이 있으면 실제 펼친 목록을 다시 대조한다. 메타데이터가 같은 경우에 대한 목록 일치 보장과 대규모·실서버 성능은 후속 검증에서 판단한다. 그 결과 별도 Helper가 필요해지면 사용자 권한·오프라인 배포 조건을 적용하고, 그때만 추가 프로그램 실행을 금지한 서버를 첫 버전의 보장 범위에서 제외한다. [소스 계약과 대안](../research/remote-watch-contracts.md)
