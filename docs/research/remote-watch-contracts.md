# 원격 변경 감시의 소스 근거

#9는 같은 구성과 펼친 폴더 집합에서 유휴 목록 조회 0회와 RTT 20 ms에서 생성·삭제·이름 변경 각각의 화면 반영 p95 1초 이하를 검증한다. 통지 유실이 확인되거나 의심되면 영향 범위의 펼친 폴더를 다시 열거하고, 범위를 특정할 수 없으면 해당 감시 범위 전체를 대조한다. ## Herdr의 공개 계약과 구현

- **폴더 감시.** App의 `watchFolder(path)`는 로컬 경로에서 다음 변경 묶음을 기다리는 취소 가능한 단발 호출이다. 반환 목록에 루트 경로가 있으면 범위 전체를 갱신한다. Mod 문서는 원격 폴더에 폴링을 안내한다. 기본 Files는 원격에서 감시를 건너뛰고, 정기 갱신 때 루트와 펼친 폴더를 다시 열거한다. 기본 주기는 10초다. [Mod 문서](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/defaults/AGENTS.md#L1252-L1267) · [Files의 감시 분기](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/defaults/mods/files/main.js#L85-L122) · [갱신 동작](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/defaults/mods/files/main.js#L160-L179)
- **원격 실행.** `exec(..., {on: space.machine})`는 로컬 `hc exec --json --on`을 거쳐 대상 core에서 프로세스를 실행한다. Core는 등록된 머신마다 프레임 연결 하나를 유지하고 이 연결로 호출을 보낸다. Core는 실행 중 stdout·stderr를 읽어 모으고 종료 처리와 출력 회수가 끝난 뒤 한 번만 반환한다. Mod의 `exec`와 `hc`는 모두 완료 결과를 담은 Promise를 제공하므로 실행 중간의 알림을 받을 수 없다. App `exec`의 제한 시간은 기본 30초, 최대 600초이며, core는 동시에 실행하는 exec를 core 인스턴스당 16개로 제한한다. [Mod 타입](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/defaults/herdr.d.ts#L4-L17) · [App 래퍼](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/src/mods.rs#L924-L950) · [`hc` Mod 바인딩](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/src/mods.rs#L1155-L1158) · [core 연결](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/crates/herdr-core/src/remote.rs#L1-L4) · [실행 한도](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/crates/herdr-core/src/exec.rs#L17-L47) · [결과 반환](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/crates/herdr-core/src/exec.rs#L189-L222)
- **Core 스트림.** 공개 OpenRPC에는 파일시스템 변경 구독이 없다. 별도의 `terminal.attach`는 터미널 출력 스트림을 보내고, `events.subscribe`는 터미널 상태와 core 문서 변경을 통지한다. 원격 core 문서의 변경 통지에는 머신·이름·버전이 들어가고, 값은 `doc.get`으로 읽는다. 단절 중 발생한 문서 변경은 재생되지 않으며 재연결 또는 `missed`에서 다시 읽어야 한다. Windows core는 명명된 파이프를 사용한다. Mod의 공개 `net`과 `websocket`은 별도 네트워크 연결용이며, 공개 Mod API에서 core 파이프나 스트림에 직접 연결하는 계약은 확인되지 않았다. [OpenRPC](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/hc.openrpc.json) · [core 연결 규약](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/README.md#L21-L30) · [터미널 스트림](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/README.md#L64-L72) · [문서 변경 통지](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/README.md#L181-L219) · [Mod 소켓 타입](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/vendor/gpui-kit/crates/shell/src/typings.rs#L3997-L4026)

## Linux의 변경 감지와 복구

- **GNU `stat` 9.7.** 대상 디렉터리의 장치·inode와 수정·상태 변경 시각(`%d`, `%i`, `%y`, `%z`)을 자식 열거 없이 읽는다. `-L`은 심볼릭 링크의 대상을 읽는다. Linux에서 직계 항목 생성·삭제는 부모 디렉터리의 mtime을 바꾸며, 이름 변경은 관련 부모 디렉터리의 수정·상태 변경 시각을 갱신 대상으로 표시한다. [GNU `stat` 설명](https://github.com/coreutils/coreutils/blob/v9.7/doc/coreutils.texi#L12926-L12960) · [출력 형식](https://github.com/coreutils/coreutils/blob/v9.7/doc/coreutils.texi#L13057-L13081) · [메타데이터 읽기 구현](https://github.com/coreutils/coreutils/blob/v9.7/src/stat.c#L1307-L1354) · [Linux `inode(7)`](https://man7.org/linux/man-pages/man7/inode.7.html#DESCRIPTION) · [POSIX `rename()`](https://www.man7.org/linux/man-pages/man3/renameat.3p.html#DESCRIPTION)
- **`stat` 사용 시의 추론.** 펼친 폴더의 메타데이터만 주기적으로 읽고 변경이 관측된 폴더를 열거하면, 유휴 목록 조회 없이 단일 변경을 탐지할 가능성이 있다. 주기적인 메타데이터 읽기와 원격 명령 비용은 남는다. 샘플에는 변경 경로, 통지 순번, 유실 표시가 없으므로 값이 같다는 이유만으로 목록의 일치나 통지 유실 복구를 보장할 수 없다. 단절이나 감시 중단으로 유실이 의심되면 실제 목록을 대조해야 한다. [GNU `stat` 계약](https://github.com/coreutils/coreutils/blob/v9.7/doc/coreutils.texi#L12926-L12960) · [SwiftTree 복구 기준](herdr-files.md#유휴-조회와-변경-감시-복구)
- **Linux inotify.** 감시는 비재귀이며 등록한 inode에 연결된다. 직계 항목의 생성·삭제와 이름 변경을 이벤트로 읽을 수 있고, 이동의 양쪽 이벤트는 같은 쿠키를 사용할 수 있다. 경로 자체가 이동하면 `IN_MOVE_SELF`가 오고, 삭제나 언마운트 등으로 감시가 해제되면 `IN_IGNORED`가 온다. 인스턴스의 파일 디스크립터를 모두 닫으면 감시가 해제된다. 큐가 넘치면 이벤트가 버려지며 `IN_Q_OVERFLOW`의 감시 번호는 `-1`이다. SwiftTree에 적용하면 펼친 폴더와 링크 대상에 필요한 감시를 등록하고, 이동·교체 시 경로와 감시의 연결을 다시 확인해야 한다. 넘친 큐에서 영향 폴더를 특정할 수 없다면 해당 인스턴스가 맡은 펼친 폴더를 모두 대조해야 한다. 갱신 중 새 감시를 등록하는 구간과 재연결에도 목록 대조가 필요하다. [Linux `inotify(7)`](https://man7.org/linux/man-pages/man7/inotify.7.html#DESCRIPTION) · [감시와 캐시의 경합](https://man7.org/linux/man-pages/man7/inotify.7.html#NOTES) · [Linux `inotify_add_watch(2)`](https://man7.org/linux/man-pages/man2/inotify_add_watch.2.html#DESCRIPTION)

## #9에서 비교할 경로

시험 환경에서 확인된 도구는 QEMU Debian 13 ext4의 GNU `stat` 9.7, `sh`, `sleep`, Python 3, Perl, `timeout`이다. `inotifywait`와 `gio`는 없었고, 해당 세션에 사용자 버스가 없어 `systemd-run --user`가 실패했다. 이는 이번 시험 환경의 제약이다. [QEMU 기준 환경](../verification/files-baseline.md#실행-환경과-3-측정값)

- **기존 core와 서버 도구.** `exec`를 통한 `stat` 폴링이나, Python의 `ctypes`로 inotify를 열고 변경 시 종료하는 제한 시간 있는 대기를 시험할 수 있다. 둘 다 기존 머신 연결을 활용한다. 후자는 명령 재등록 사이의 공백과 동시 실행 한도를 검증해야 한다. 지속 감시를 터미널 스트림 또는 core 문서 통지에 연결하는 방안도 공개 전송 기능으로 설명할 수 있으나, 감시 생산자와 Windows Mod 수신 경로가 추가로 필요하다. [Python `ctypes`](https://docs.python.org/3.13/library/ctypes.html) · [원격 터미널 실행](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/docs/commands.md#L484-L509) · [core 문서 통지](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/README.md#L181-L219)
- **전용 Helper.** 같은 inotify 인스턴스를 유지하면 호출마다 감시를 새로 등록하는 공백을 피할 수 있다. 감시 상태·범위 변경·유실 신호를 Mod에 전하는 경로와 종료·재연결·업데이트를 함께 검증해야 한다. ADR은 필요성이 확인된 경우 관리자 권한이나 서버 인터넷 접속 없이 사용자 권한으로 배포·실행할 수 있는 Helper를 허용한다. [Linux `inotify(7)`](https://man7.org/linux/man-pages/man7/inotify.7.html#DESCRIPTION) · [배포 조건](../adr/0001-remote-helper.md)
- **Upstream 개선.** 원격 core가 파일 변경을 구독하고 기존 머신 연결을 통해 App에 통지하며, Mod가 유실·감시 취소·재연결을 다룰 수 있는 API를 추가하는 방안이다. 별도 SwiftTree Helper 배포와 비교할 비용은 App·core 양쪽 변경, 버전 호환, 릴리스 반영이다. 현행 계약은 원격 호출 라우팅과 별도 이벤트 스트림까지 제공한다. [core 라우팅](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/crates/herdr-core/src/remote.rs#L842-L855) · [core 이벤트 규약](https://github.com/herdrdev/herdr-core/blob/329cb66ebce5eca3d917fcf7364a099046979b49/schema/README.md#L115-L148) · [현행 Mod 파일 감시](https://github.com/herdrdev/herdr-app/blob/9a9ae13d998e6ed74c76e8eb13bdeb2e1420f50c/defaults/herdr.d.ts#L510-L530)
