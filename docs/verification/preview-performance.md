# 확대 미리보기 첫 화면 검증

Windows 11 Pro 빌드 26300, Intel Core Ultra 7 255H, Herdr App 0.1.18, Herdr Core 0.1.22, WebView2 Runtime 158.0.4370.45에서 측정했다. 격리 Herdr 창의 클라이언트 크기는 1600×1025, 확대 창의 Windows Graphics Capture 프레임은 1290×804였다.

Windows NTFS와 QEMU의 SSH Linux/ext4에 각각 8 MiB 원문과 280개 번호 섹션, 95,419개 공백 구분 단어를 포함한 설계서 두 개를 준비했다. 설계서에는 문서 끝의 참조 정의, 코드 펜스, Mermaid, 인라인·블록 수식이 있다. Files의 첫 본문과 문서 끝이 자료별로 구분된다. [자료 생성 및 캡처 절차](windows-native-ui.md#장문-첫-화면-시간)

## 설치와 조작

외부 HTTPS가 거절되는 프록시를 지정하고 준비한 ZIP에서 격리 Herdr에 새로 설치했다. 별도 프로필에서는 실제 v1.1.0 릴리즈의 ZIP으로 설치해 이전 Files 프로세스가 실행 중인 상태에서 같은 후보로 업데이트했다. 설치 전후 기본 Herdr 레이아웃의 해시가 같았다.

Windows와 SSH에서 Files로 원문과 Markdown을 열었다. 설계서의 첫 페이지에 머물 때 마지막 Mermaid 모듈을 읽지 않는 것을 관측했다. 일반 참조 링크로 마지막 섹션에 이동한 뒤 해당 모듈이 요청됐고, 아래로 스크롤해 다이어그램과 수식을 확인했다. 원문 전환 뒤 8 MiB 파일과 설계서의 마지막 표식으로 이동했다.

## 표본 판정

실제 **크게 보기** 클릭 직전 QPC 시각을 같은 시간축의 Windows Graphics Capture 프레임과 대조했다. 로딩 창은 완료 판정에서 제외했다. 파일마다 다른 본문 표식을 확인하고 해당 요청의 네이티브 기록과 맞췄다. Markdown의 첫 Mermaid와 첫 블록 수식은 각각 별도의 프레임으로 확인했다.

콜드 조건은 테스트 프로필에서 확대 프로세스를 종료한 뒤 입력했다. WebView2 사용자 데이터와 디스크 캐시는 유지했다. 예열 후 다른 파일은 A와 B를 교대로 열었고, 같은 파일은 아래 미리보기에 열린 파일을 다시 확대했다. p50은 중앙값, p95는 최근접 순위로 계산했다. 표본별 QPC 시각과 중간 단계는 `samples.json`에 저장했다.

Windows 예열 상태에서 두 열기 조건 중 더 느린 p95는 8 MiB 원문 114.5 ms, 장문 Markdown 270.3 ms였다. 각각 250 ms와 500 ms 목표를 충족했다.

NTFS 원문에서 가장 느린 콜드 표본은 첫 본문까지 2,424.6 ms가 걸렸다. 이 표본에서 WebView2 준비가 클릭 후 2,355.1 ms에 끝났고 파일 선두 범위는 2,371.4 ms에 전달됐다. SSH 장문 콜드 구간의 가장 느린 표본은 7,756.8 ms였고 WebView2는 6,707.8 ms에 준비됐다.

첫 페이지에서 마지막 다이어그램을 미리 요청했던 기준 버전과 재측정 때 발견한 이전 WebView2 프레임은 별도 증거로 남겼다. 표에는 새 본문이 확인된 최종 설치 후보의 표본을 사용했다.
