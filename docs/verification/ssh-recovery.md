# SSH 단절과 복구 검증

[#14](https://github.com/kalstein00/herdr-swift-tree/issues/14)는 Windows Herdr에서 SSH 연결이 끊겼을 때 이미 읽은 내용을 계속 탐색하고, 다시 연결한 뒤 실제 목록과 탐색 위치를 복구하는 동작을 검증한다.

1. 시험 전용 SSH 머신과 space에 `OpenSmall`, `Shelf`, `Unread` 폴더를 만든다. `Shelf`에는 스크롤이 필요한 정도의 텍스트 파일을 둔다. 앞의 두 폴더만 펼치고 `Shelf` 아래 파일을 열어 본문을 표시한다.
2. 해당 SSH 전송만 끊는다. 읽은 목록을 스크롤하고 `OpenSmall`을 접었다 다시 펼친다. `Unread`는 처음 펼쳐 대기 문구를 확인한다. 스크롤을 움직여 화면에 남아 있는 기존 행 하나를 선택한다.
3. 별도의 유지보수용 SSH 연결로 펼친 폴더의 파일을 추가하거나 이름을 바꾼다. 선택한 행보다 앞에도 여러 항목을 추가한다. 실제 파일시스템 목록을 별도로 기록한다.
4. 시험 연결을 복구하고 열린 폴더의 전체 목록을 기준 목록과 비교한다. 다시 연결하기 직전과 복구 직후 같은 행이 선택되어 있는지와 뷰포트에서의 위치를 확인한다.
5. SSH가 연결된 상태에서 그 시험 공간의 메타데이터 감시 요청 하나를 원격에서 종료한다. 두 폴더를 바꾸고, 바꾸지 않은 폴더까지 모든 펼친 폴더가 다시 읽혔는지 파일시스템과 목록에서 확인한다.

## 관측 결과

Windows 11 Pro 26300, 네이티브 Herdr App 0.1.18 및 core 0.1.22, 1600×1025 창에서 검사했다. SSH 대상은 Debian 13.8의 ext4였다. 시험 머신의 세션은 로컬 TCP 중계기로 기존 SSH 포트에 전달했다. 중계기가 시험 연결만 끊고 새 연결을 차단하는 동안 기존 SSH 주소에서는 데이터를 계속 변경할 수 있었다. Herdr Core에서도 시험 머신이 `unreachable`로 바뀌는 것을 확인했다.

기존 후보에서는 단절 후 읽은 행과 미리보기가 남았고 감시 중단 문구가 표시됐다. 수정한 설치본에서는 **연결 끊김 · 마지막으로 확인한 내용**이 나타났고, 목록을 스크롤하거나 다시 펼친 폴더에서도 읽은 내용이 보였다. `Unread`를 펼치면 **연결 후 불러올 수 있음**이 표시됐다. 미리보기의 `cached preview row 148` 본문이 유지됐다.

SSH 단절 중 `Shelf`에 앞쪽 행 24개를 추가하고 파일 이름을 바꿨다. `OpenSmall`의 이름 변경과 `Unread`의 새 파일도 사용자 재조작 없이 보였다. `row-124.txt`는 복구 전후에 선택 상태였다. 단절 안내가 사라져 목록의 시작 위치와 선택 행이 창에서 각각 38px 위로 이동했으며, 목록 안에서의 선택 행 위치와 주변 행은 유지됐다.

선택한 `row-148.txt`를 화면 밖에 두고 다시 시험했다. 보고 있던 행 중 `row-095.txt`만 남기고 앞에 파일 100개를 추가했다. 수정한 설치본에서는 재연결 후 `row-095.txt`가 목록 안의 같은 위치에 보였고, `↓`를 한 번 누르자 기존 선택의 다음 행인 `row-149.txt`가 선택됐다. `row-148.txt`의 미리보기는 그대로였다.

실제 창에 표시하는 행을 읽기 전용으로 기록한 별도 실행에서 각 폴더의 이름, 순서, 유형을 독립적인 `os.scandir` 목록과 전체 대조했다.

| 시나리오 | 루트 | OpenSmall | Shelf | Unread | 누락 / 추가 / 중복 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 재연결 | 3 | 2 | 176 | 3 | 0 / 0 / 0 |
| 감시 요청 중단 | 3 | 3 | 177 | 3 | 0 / 0 / 0 |

감시 요청 중단 검증에서 Linux `inotify`는 루트와 세 하위 폴더의 실제 읽기를 포착했다. 루트와 `Unread`에는 파일 변경을 주지 않았다. 독립 열거로 센서의 양성 대조를 수행했다. 정상 감시가 이어진 30.03초 동안 같은 네 경로의 내용 읽기는 없었다. 목록 기록용 코드를 제거하고 설치된 소스 해시가 저장소와 일치하는지 재확인했다.

검사한 설치본 캡처는 작업의 로컬 `ticket-14`에 보관했다. `final-offline-tree-preview.png`에 단절 안내와 미리보기, `final-offline-unread.png`에 대기 행, `final-anchor-before.png`와 `final-anchor-after.png`에 복구 전후 기준 행이 있다. `final-selection-continued.png`에서 화면 밖에 있던 선택이 이어졌음을 확인할 수 있다. 같은 위치에 중계기의 차단 기록, 파일시스템 기준 목록, 전체 대조 결과와 읽기 센서 기록도 있다.
